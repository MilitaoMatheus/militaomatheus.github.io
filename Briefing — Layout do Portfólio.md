# Briefing — Layout do Portfólio

## 1. Objetivo

Criar um portfólio pessoal moderno, profissional e visualmente marcante para apresentar minha trajetória como desenvolvedor, meus projetos, habilidades, experiências e formas de contato.

O site deve transmitir:

- Tecnologia
- Profissionalismo
- Criatividade
- Organização
- Modernidade
- Personalidade
- Facilidade de navegação

O portfólio deve funcionar tanto como **apresentação profissional** quanto como **cartão de visita digital**.

---

# 2. Direção visual

## Estilo

O design deve seguir uma estética:

- Minimalista
- Moderna
- Dark
- Tecnológica
- Elegante
- Com bastante espaço negativo
- Visualmente organizada
- Sem excesso de elementos

Evitar um design genérico de "portfólio de programador".

A interface deve parecer um produto digital profissional, e não apenas uma página com uma lista de projetos.

---

# 3. Tema

## Tema principal

Utilizar **Dark Mode** como padrão.

### Características

- Fundo predominantemente escuro
- Cards com tonalidade ligeiramente diferente do fundo
- Bordas discretas
- Contraste alto para textos importantes
- Elementos secundários em tons de cinza
- Uma cor de destaque para botões, links e detalhes visuais

A cor de destaque deve ser utilizada com moderação.

---

# 4. Tipografia

Utilizar uma fonte moderna e limpa.

Sugestões:

- Red Hat Display
- Inter
- Poppins
- Manrope

### Hierarquia

#### Títulos principais

Devem ser grandes, fortes e chamativos.

Exemplo:

> Olá, eu sou Matheus.

#### Subtítulos

Utilizar peso intermediário e tamanho menor.

#### Texto

Deve possuir excelente legibilidade, evitando textos muito pequenos.

---

# 5. Estrutura geral

O portfólio deverá possuir as seguintes seções:

1. Navbar
2. Hero
3. Sobre mim
4. Skills / Tecnologias
5. Experiência
6. Projetos
7. Contato
8. Footer

A navegação deve permitir acesso rápido às principais seções.

---

# 6. Navbar

A navbar deve ficar no topo da página.

### Elementos

À esquerda:

**Meu nome / Logo pessoal**

À direita:

- Início
- Sobre
- Experiência
- Projetos
- Contato

Também pode existir um botão:

> Vamos conversar

### Comportamento

A navbar deve:

- Ser responsiva
- Permanecer visível durante a navegação
- Possuir efeito visual discreto ao realizar scroll
- Não ocupar muito espaço vertical

Em dispositivos móveis, transformar os links em menu hamburger.

---

# 7. Hero Section

A primeira seção deve causar impacto visual imediatamente.

## Estrutura

Layout dividido em duas áreas:

### Lado esquerdo

Apresentação.

Exemplo:

> Olá, eu sou  
> **Matheus Militão.**

Abaixo:

> Desenvolvedor apaixonado por tecnologia, desenvolvimento de software e criação de soluções digitais.

Adicionar um pequeno elemento indicando a área de atuação.

Exemplo:

`Desenvolvimento de Software • Tecnologia • Dados`

### Botões

Adicionar dois CTAs:

**Principal**

> Ver meus projetos

**Secundário**

> Entre em contato

---

# 8. Elemento visual do Hero

O Hero deve possuir um elemento visual tecnológico.

Pode ser:

- Foto profissional
- Ilustração
- Avatar
- Elemento abstrato
- Interface estilizada
- Código visual
- Animação discreta

O elemento visual não deve competir com o texto principal.

Também pode ser utilizado um background visual sutil, como:

- Gradientes
- Grid
- Glow
- Linhas
- Partículas
- Formas geométricas

Evitar exageros.

---

# 9. Indicador de Scroll

Na parte inferior do Hero, adicionar um indicador discreto:

> ↓ Role para explorar

Pode possuir uma pequena animação.

---

# 10. Sobre Mim

Criar uma seção apresentando minha trajetória.

## Layout

Utilizar duas colunas.

### Coluna esquerda

Título:

> Sobre mim

Texto apresentando:

- Formação
- Interesse por tecnologia
- Experiência profissional
- Desenvolvimento de projetos
- Interesse em desenvolvimento de software
- Aprendizado contínuo

### Coluna direita

Criar pequenos cards com informações relevantes.

Exemplo:

**Formação**

Desenvolvimento de Software Multiplataforma

**Experiência**

Planejamento e análise

**Foco**

Desenvolvimento de Software

**Interesses**

Tecnologia, produtos e inovação

Criar uma seção para apresentar minhas principais tecnologias.

Título:

> Tecnologias & Skills

Organizar as tecnologias em categorias.

### Front-end

- HTML
- CSS
- JavaScript

### Back-end

- Python
- Java
- PHP
- Spring Boot

### Mobile

- Dart

### Banco de Dados

- SQL

# 12. Apresentação das Skills

Não utilizar apenas uma lista simples.

Cada tecnologia pode ser apresentada através de:

- Cards
- Ícones
- Badges
- Pequenos elementos visuais

Os cards devem possuir:

- Ícone
- Nome
- Categoria
- Pequena interação no hover

Exemplo:

```text
┌──────────────────────┐
│  ◉                   │
│  Python              │
│  Backend             │
└──────────────────────┘
```

---

# 13. Experiência

Criar uma timeline profissional.

Título:

> Minha experiência

Cada experiência deve possuir:

- Empresa
- Cargo
- Período
- Descrição
- Principais responsabilidades
- Tecnologias/ferramentas utilizadas

A timeline deve ser visualmente limpa.

Exemplo:

```text
● 2026
│
│  Empresa
│  Cargo
│
│  Descrição da experiência
│
● 2025
│
│  Empresa
│  Cargo
```

---

# 14. Projetos

Esta deve ser uma das principais seções do portfólio.

Título:

> Projetos em destaque

Os projetos devem ser apresentados através de cards grandes.

Cada card deve possuir:

- Imagem/preview
- Nome
- Descrição
- Tecnologias
- Tags
- Link para GitHub
- Link para demonstração, quando disponível

---

---

# 16. Projeto em destaque

Além dos cards normais, destacar um projeto principal.

Esse projeto pode ocupar uma área maior da página.

Estrutura:

### Esquerda

Preview do projeto.

### Direita

- Nome
- Descrição
- Problema solucionado
- Tecnologias
- Links

Exemplo:

> Estalo

> Plataforma de recomendação de experiências baseada nos interesses e contexto do usuário.

---

# 17. Filtros de projetos

Opcionalmente, adicionar filtros:

- Todos
- Front-end
- Back-end
- Full Stack
- Mobile
- Outros

Os filtros devem permitir visualizar os projetos por categoria.

---

# 18. Seção de números

Criar uma pequena seção com métricas.

Exemplo:

```text
+10
Projetos

+5
Tecnologias

+2
Anos estudando tecnologia

∞
Curiosidade
```

Os números não devem ser inventados.

Utilizar somente informações reais.

---

# 19. Contato

Criar uma seção final chamativa.

Título:

> Vamos criar algo juntos?

Texto:

> Estou sempre aberto a novas oportunidades, projetos e conexões.

Adicionar botões para:

- LinkedIn
- GitHub
- E-mail

Também pode existir um formulário simples:

- Nome
- E-mail
- Mensagem
- Enviar

---

# 20. Footer

Footer minimalista.

Elementos:

- Nome
- Pequena descrição
- Links sociais
- Copyright

Exemplo:

> Desenvolvido por Matheus Militão.

Adicionar uma pequena frase relacionada à tecnologia.

---

# 21. Animações

As animações devem ser **sutis e profissionais**.

Utilizar:

- Fade-in
- Slide-up
- Hover
- Transições suaves
- Pequenos efeitos de escala
- Animações durante o scroll

Evitar:

- Animações exageradas
- Elementos piscando
- Muitas partículas
- Transições lentas
- Efeitos que prejudiquem a navegação

---

# 22. Responsividade

O site deve ser totalmente responsivo.

Priorizar:

### Desktop

Experiência visual completa.

### Tablet

Reorganização das colunas.

### Mobile

Layout vertical.

No mobile:

- Navbar compacta
- Menu hamburger
- Hero em coluna
- Cards ocupando praticamente toda a largura
- Textos adaptados
- Botões com tamanho confortável
- Evitar elementos horizontais que causem scroll

---

# 23. UX

A experiência deve ser simples e intuitiva.

O visitante deve conseguir responder rapidamente:

1. Quem é o Matheus?
2. O que ele faz?
3. Quais tecnologias ele conhece?
4. O que ele já desenvolveu?
5. Qual foi sua experiência?
6. Como entrar em contato?

Todas essas respostas devem estar disponíveis sem exigir navegação complexa.

---

# 24. Microinterações

Adicionar pequenas interações para tornar a interface mais interessante.

Exemplos:

- Hover nos botões
- Hover nos cards
- Ícones com pequenas animações
- Links com underline animado
- Elementos aparecendo durante o scroll
- Cursor/interações sutis

As microinterações devem melhorar a experiência, não apenas existir por estética.

---

# 25. Acessibilidade

O projeto deve considerar:

- Contraste adequado
- Textos legíveis
- Navegação por teclado
- Labels em formulários
- Alt text nas imagens
- Botões claramente identificáveis
- Estados de hover/focus
- Respeito à preferência de redução de movimento

---

# 26. Performance

O layout deve ser visualmente rico sem prejudicar o carregamento.

Priorizar:

- Imagens otimizadas
- Lazy loading
- Animações leves
- Poucos recursos externos
- Código organizado
- Evitar vídeos ou efeitos pesados sem necessidade

---

# 27. Diretrizes de Design

### Fazer

- Usar bastante espaço negativo
- Criar hierarquia visual clara
- Utilizar cards
- Utilizar bordas discretas
- Utilizar animações pequenas
- Destacar projetos
- Criar uma identidade visual própria

### Evitar

- Excesso de gradientes
- Excesso de neon
- Muitos elementos na tela
- Textos gigantes sem propósito
- Carrosséis desnecessários
- Barras de progresso para representar conhecimento
- Design genérico de template

# 29. Resultado esperado

O resultado final deve parecer um **portfólio profissional de um desenvolvedor moderno**, com forte identidade visual e foco nos projetos.

A prioridade deve ser:

**1. Identidade visual**  
**2. Experiência do usuário**  
**3. Projetos**  
**4. Clareza das informações**  
**5. Responsividade**  
**6. Performance**

O visitante deve entrar no site e entender rapidamente quem sou, o que faço e quais projetos já desenvolvi.

O design deve transmitir a sensação de:

> "Esse desenvolvedor se preocupa tanto com a qualidade do produto quanto com o código por trás dele."
